# V3 — 同步启动版(去掉逐轮标定)

本目录是**第三版**。核心变化:**去掉每次启动时的逐个标定,四轮同步启动**。
前两版(根目录 V1、`V2_反向标定版/`)原样保留。

## 这一版做了什么

| 改前 | 改后 |
|------|------|
| 启动 → FL转 → RL转 → RR转 → FR转 → 开始测试 | 启动 → **四轮同步**开始测试 |
| 每次标定浪费 ~4 秒 | **零等待** |
| 标定失败还要排查 | 直接跑 |

## 具体改动

### 1. `motor_closed.py` — `ClosedMotor` 加 `sign` 参数

```python
# 改前
def __init__(self, ..., invert_dir=False):
    self.sign = 1      # 默认值, 靠 calibrate_sign() 覆盖

# 改后
def __init__(self, ..., invert_dir=False, sign=None):
    self.sign = sign if sign is not None else 1
```

**为什么**：以前 `sign` 只能通过 `calibrate_sign()` 动态测得(让轮子转一圈、读编码器方向)。现在允许构造时**直接传入已知值**,跳过动态标定。`calibrate_sign()` 逻辑保留作备用。

### 2. `test_chassis.py` — 硬编码 sign + 删标定块

```python
# 改前
MOTORS = (
    ("FL", 1, 61, 14, 15, 17, 27, False),        # 无 sign
    ...
)
# 改后
MOTORS = (
    ("FL", 1, 61, 14, 15, 17, 27, False, -1),    # sign=-1
    ("RL", 2, 46, 36, 37, 40, 41, True,  -1),
    ("RR", 3, 47,  3,  4,  5,  6, True,  +1),
    ("FR", 4, 52, 32, 33, 34, 35, False, +1),
)
```

删掉了整段逐轮标定(原先的 `bad = chassis.manager.calibrate()` 等)。

**为什么**：日志已确认 `sign` 值稳定,每次重复标定纯属浪费时间。删掉后**上电直接跑差速动作**。

### 3. `test_forward.py` — 同上

改动完全一样：`MOTORS` 加 `sign`、删 `calibrate()` 块,四轮同步前进。

## `test_chassis.py` 兼作"健康检查"

`test_chassis.py` 是一个 PID 闭环、目标速度恒定的稳态场景,非常适合当**在线自检**用:

- **四轮全非零** → 四路(编码器 / 驱动 / PWM / 电源)都通了,线路正常。
- **速度全 0** → 大概率没上电,优先查电源。

因为它是**稳态闭环**(`set_velocity(+400)` 期望恒速 +400),0 只有"异常"这一种含义,信号干净、判据明确。

> 对比 `test_forward.py`:它带着惯性/滑行的动态过程,速度会经历 0→加速→滑行→0,0 同时可能是"起点/终点"也可能是"没上电",语义有歧义,**不适合当健康判据**。

## 实测速度调参依据(最佳巡航速度 = 700 Hz)

对 `test_forward.py` 做了全速度档实测(`sign: FL=-1, RL=-1, RR=+1, FR=+1`,STBY=GPIO2),两次运行高度可重复:

| 档位 | 目标 | 实际波动 | 占空比 | 剩余余量 | 距离效率 |
|------|:---:|:---:|:---:|:---:|:---:|
| 低速 | 300 Hz | ±15 Hz | ~15% | 45% | 基准 |
| **中速✅** | **700 Hz** | **±10 Hz** | **~33%** | **27%** | **4×** |
| 高速 | 1100 Hz | ±6 Hz | ~52% | 8% | 7× |

**为什么 700 Hz 是最佳巡航:**

1. **占空比仅 33%,剩 27% 余量**应对转弯差速与负载变化(1100 Hz 只剩 8%,转弯差速易顶到 60% 限幅失速)。
2. **距离效率 4 倍于 300 Hz**,实际跑不慢。
3. **精度 ±10 Hz(1.4%)**,和高速档几乎一样稳。
4. `占空比/速度 ≈ 4.7% 每 100 Hz`,三档强线性,说明 PI + 前馈(ff≈0.05)在全速度区间都成立,700 落在线性最干净的区段。

**结论**:四轮一致性良好、PI 闭环全程稳定、换向对称无抖动、倒车 duty 与正转完全对称。日常循迹送药以 **700 Hz 巡航**;1100 Hz 仅在冲刺段偶尔使用,不建议当常驻速度。

## 串口全 0 + duty 固定:排查与诊断

**现象**:`test_forward.py` 运行时,FL/RL/RR/FR 速度全为 0,且 duty 固定不变。

**诊断(关键认知)**:`FL/RL/RR/FR` 那列是编码器实测速度,duty 那列是 PID 输出。速度恒为 0 → 误差恒等于目标值 → PI 积分持续累加直至**饱和** → 输出停在常数,**duty 固定是"无反馈"的必然结果,不是 PID 逻辑出错**。PID 其实在满负荷驱动,只是编码器一直报告"没动"。

**证据链**(`sign: FL=-1, RL=-1, RR=+1, FR=+1`):

| 目标 | 实际速度 | duty | 组成 |
|------|:---:|:---:|------|
| +300 Hz | 0 | 35 | ff×300(=15) + PI饱和(=20) |
| +700 Hz | 0 | 55 | ff×700(=35) + PI饱和(=20) |
| +1100 Hz | 0 | 60 | ff×1100(=55)+PI(=20)=75,被 `out_limit=60` 截断 |
| -300 Hz | 0 | -35 | 对称,一致 |

**对比(有速度反馈时)**:
```
t= 300ms  FL= +307  RL= +306  ...  duty=[14, 14, 14, 14]   ← 速度正常,duty 只要 ~15%
```
有反馈 duty 只需 14~15%;无反馈被拉到 35~60% 仍在徒劳。这就是"有反馈 vs 无反馈"的本质区别。

**排查优先级**(四路编码器同时挂的概率极低,先查电源侧):
1. **驱动板电源**未上电 → 电机不转 → 编码器自然读到 0。
2. **STBY(GPIO2)未拉高** → 电机使能未打开(确认初始化时序:先拉高 STBY 再给 PWM)。
3. **编码器供电 / 共地线**松动。

**一句话诊断思路**:duty 是"PID 想要的结果",速度是"实际发生的结果";duty 固定 + 速度全 0 = 电机有驱动命令但没转动/没反馈,优先查"为什么没转",而非"PID 逻辑"。
